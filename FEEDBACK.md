# How to give feedback

Thank you for trying Apostil. Short notes help as much as long ones.

## Where

Open an issue in this repo. There are two forms: "Something does not work" and "What I think". Your agent can write it with you ("I want to report an issue about Apostil"), or run "Apostil: Report an Issue" in VS Code; both open the form with your versions filled in, and you submit it yourself. If you do not want to write an issue, send your notes to the person who invited you.

## What helps most

1. **What you tried**, in one line: your own repo, a pull request.
2. **What you expected, and what you saw.** A screenshot says a lot.
3. **The output of `apostil doctor`**, when something did not work. It holds no code and no token.
4. Your agent app and its version (Claude Code or Codex), and your version of VS Code.

Please do not paste code of your own repo that you may not share.

## Questions that we would like an answer to

You do not have to answer all of them.

- What is Apostil for, in your own words?
- Which view helped you most to understand a change, and which did you not use?
- Was a diagram wrong, or did a note say something that the code does not do? What did you do then?
- Did the description of your own change come out right the first time? How long did the agent take?
- "Diffs" with the diagram beside it, and Option+Down from change to change: did you read a whole change this way?
- Did you send a comment to an agent from Apostil? Did the answer come back where you expected it?
- What did you miss? What was in your way?
- Would you use it again next week? Why, or why not?
